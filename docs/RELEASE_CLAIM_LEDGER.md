## 1. Truth in Advertising Protocol

Every claim made across `README.md`, `docs/demo_script.md`, `docs/judge_evidence.md`, web UI headers, and video voiceovers is audited below. Classifications describe the evidence and limits below; they must change when the source or verification changes. This refresh addresses state concurrency, dependency pinning and current documentation. It is not a fresh exhaustive release audit or a browser pass. The unchanged historical source facts retain their earlier audit attribution.

Each claim has a status:
- **VERIFIED:** Directly backed by executable code, passing regression tests, or direct source data checks at the stated snapshot; local source inspection and component tests do not establish browser, field or production behavior.
- **BOUNDED_ASSUMPTION:** Declared engineering approximation or simulation model; explicitly disclosed as an assumption to judges and users.
- **DISCLOSED_LIMITATION:** Known technical boundary or pending gate item; transparently disclosed with zero false claims of completion.
- **PROHIBITED:** Explicitly forbidden claim (e.g. live utility dispatch, measured dollar savings, 100% AI accuracy).

## 3. Mandatory Presentation & Video Guidelines

During the 3-minute video presentation and Zoom Q&A with AEP judges, all presenters must adhere strictly to the following language standards:

1. **Say:** *"We ingest real AEP GIS shapefiles and validated 117,549 customer paths offline. The interactive web demo runs on an anonymized 16-premise sample."*  
   **Do NOT say:** *"The web app models all 117,000 customers in real time."*
2. **Say:** *"We apply the verified AEP STORMS labor rate from workbook cells C21 and D21 multiplied by 4.5 once, yielding 8.974 person-hours for a declared 25-kVA replacement."*  
   **Do NOT say:** *"Our AI predicted the repair will take 2.99 hours."*
3. **Say:** *"When telemetry is contradictory, Sentinel abstains: it sets status to Under Review, marks risk as Unknown, and refuses to guess a premature restoration time."*  
   **Do NOT say:** *"Our system always knows when power will be restored."*
4. **Say:** *"Critical facilities are spatially linked to nearest transformers as a planning assumption; physical electrical connectivity is not verified."*  
   **Do NOT say:** *"Our system restores power to the local hospital."*
5. **Say:** *"Cutout switch and sensor telemetry are modeled scenario evidence to demonstrate causal decision triage."*  
   **Do NOT say:** *"We installed IoT sensors on live AEP distribution poles."*

## 4. LRP-150 state and CI changes

`IncidentProvider` uses one monotonic sequence counter across scenario selection, asset selection and reset. Superseded successes, failures and finalizers do not change the current snapshot, selected IDs, action error or busy indicator. Delayed initialization also cannot replace a later selected incident or mark it disconnected. This guards client results; it does not cancel in-flight server mutations or prove cross-client request ordering. The local 38-case harness uses the real bundled provider/API with deferred fetch and deterministic React hooks.

The AEP integration workflow installs Python packages with `python -m pip install -r requirements.txt`, then compiles and runs `python -m pytest -q tests/`. The requirements file is unchanged and pins direct dependencies. This change does not lock transitive dependencies or establish that a clean install or hosted CI has passed.

The operator Supply Path subtitle states: “Supplied dependency paths from circuit breaker to sample premises; upstream connection beyond breaker unknown.” The Dusk shell and current customer/operator views are described in the judge evidence; local compilation is not a visual acceptance result.
