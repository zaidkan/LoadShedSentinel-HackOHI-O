## Coordinate reference systems and geometry

**G — geographic WGS 84:** source WKT starts `GEOGCS["GCS_WGS_1984"...]`, horizontal longitude/latitude in degrees, represented as EPSG:4326 by the importer. GeoJSON coordinates are `[longitude, latitude]`. Geographic degrees are not metres or validated electrical distance.

**M — WGS 1984 Web Mercator Auxiliary Sphere:** source WKT starts `PROJCS["WGS_1984_Web_Mercator_Auxiliary_Sphere"...]`, horizontal metres, consistent with Web Mercator/EPSG:3857. The three facility layers also declare `VERTCS["NAVD_1988"...]` in metres. They are inventoried in source CRS, not reprojected or included in the current public slice.

Shapefile type **11** is PointZ; type **3** is PolyLine. Z values and elevations have not been validated or used for asset height/flood analysis. Current geometry ingestion supports only the supplied geographic point layers, validates coordinate bounds, and performs **zero geometry repairs**. It rejects unsupported CRS rather than guessing a transform. Line layers are counted and described, not converted to electrical graph edges.

## Key quality and null semantics

Identifiers remain strings, including leading-zero premise IDs, circuit IDs, location references and numeric-looking DBF IDs. Never join by row position, map proximity, rounded coordinates, or integer coercion.

| Check | Verified result | Interpretation |
|---|---:|---|
| Customer premise keys | 117,642 distinct; 0 duplicate keys | Customer join identity |
| Customer transformer references | 25,309 distinct | Repeated references are expected one-to-many service relationships |
| Transformer location keys | 26,950 distinct across 26,959 rows | 8 duplicated values account for 9 excess rows |
| Raw customer-transformer key existence | 117,615 rows; 25,303 referenced keys match | Existence alone does not establish an unambiguous match |
| Fuse location keys | 6,698 distinct; 885 duplicated values | Location-only lookup is unsafe |
| Recloser location keys | 330 distinct; 1 duplicated value | Resolve with context or abstain |
| Switch location keys | 885 distinct; 15 duplicated values | Resolve with context or abstain |
| Missing upstream references | Transformer 526; fuse 19; recloser 3; switch 900 | Do not fill gaps with nearest equipment |
| Pole installation date blanks | 53,249 of 107,013 | No complete asset-age inference |

Inventory null rates count **blank fields**. Nonblank sentinels such as `19000101`, zero placeholders and `N/A` are not counted as null and must not be treated as complete observations. Customer address-related columns being blank does not make the remaining raw source safe: precise geometry, annotations, street context and sensitive service flags are still private.

## Upstream text and accepted graph

[matched_upstream.zip](../aep_challenge_hack26/data/raw/matched_upstream.zip) contains `matched_upstream.txt`: **117,599 distinct premise keys**, **32,600 distinct table/object equipment identities**, and **2–13 equipment entries** per line.

Format is a tab-separated premise followed by ordered `table*object_id*equipment_kind*location_reference` entries, downstream to upstream. Paths start at a distribution transformer and end at a supplied circuit breaker; intermediate kinds include fuse, hydraulic/electronic recloser, step equipment and sectionalizer. Private equipment keys are `table:object_id`; they do not rely on location uniqueness. Duplicate premises, conflicting equipment metadata, repeated equipment or malformed endpoints are rejected.

Acceptance requires one customer row, an exact text-premise match, agreement of first transformer location and final circuit identifier, and an unambiguous GIS transformer match using location/type/circuit, with exact source ID where appropriate. It does not require inventing GIS geometry for text-only intermediate equipment.

Impact lookup indexes explicit accepted premise paths; it does not traverse conflicting branches as if one consistent electrical model were established. Multiple fault footprints are set unions, not summed counts. Rejected premises make impact estimates coverage-limited. Unknown assets/premises return `UNKNOWN` rather than a fabricated link or a known-zero outage count. A known supplied path ends at the breaker: **physical substation connectivity remains UNKNOWN**, even where GIS reports a station label.

Public seed is `PREM-000001`; public asset tokens use `ASSET-`. Tokens identify the supplied snapshot, not stable identities across future source revisions. Public coordinates are rounded to **0.01 degrees**; no customer coordinates, sensitive service attributes, addresses or raw premise IDs are exported. Link geometry is labelled `schematic_link_not_conductor`. No breaker position is invented. Equipment positions are unsuitable for household navigation or engineering work.

Serve an explicit safe artifact, never the processed directory wholesale. Git does not preserve owner-only read permissions; reapply private-file/directory permissions after checkout or copy on POSIX. Windows chmod does not establish an owner-only ACL. Selection of a real public path does not automatically replace the scenario generator's independently declared `P-DEMO-` premise groups.

### Runtime data continuation

Run `python -m pipeline.build_graph` before starting the API or running the complete
API tests on a fresh clone. The private graph is intentionally not tracked. The
new `ensure_runtime_data` helper validates source hashes and persisted tokens,
reuses a valid graph, and repairs stale/missing public outputs using a manifest
written last. After bootstrap the current topology endpoint returns a known
four-equipment path for `PREM-000001` instead of HTTP 503.

Additional safe artifacts are `source_context.json` (public catalog plus complete
bounded local/upstream groups), `risk_context.json` (dated report aggregates for

matched transformer, with declared ordinal scenario weights and no calibrated
probability claim. It imports no household coordinates.
